# TwoTower (loopback): Last.fm 1K и MovieLens-100k

Практика по дисциплине «Рекомендательные системы»: взять опубликованный алгоритм, воспроизвести его результаты на демонстрационном датасете авторов, обучить на принципиально другом датасете и сравнить метрики с заявленными.

| | |
|---|---|
| Алгоритм | TwoTower — [DanielRegaladoCardoso/loopback-twotower](https://huggingface.co/DanielRegaladoCardoso/loopback-twotower) |
| Демонстрационный датасет | [lastfm-1k-twotower](https://huggingface.co/datasets/DanielRegaladoCardoso/lastfm-1k-twotower): прослушивания музыки, 992 пользователя, 1.5 млн треков, 19 млн событий |
| Другой датасет | [movielens-100k](https://huggingface.co/datasets/DukeNLPGroup/movielens-100k): оценки фильмов, 943 пользователя, 1682 фильма, 100 тыс. оценок |

## Быстрый старт

```bash
bash scripts/predict.sh            # веса + датасет → вероятности следующего фильма, MovieLens-100k
WEIGHTS=weights/twotower_ml100k_logq.pt bash scripts/predict.sh   # то же на весах модели с logQ
bash scripts/predict.sh lastfm 2   # то же для Last.fm 1K на весах авторов (скачает около 620 МБ)
bash scripts/run_all.sh            # всё исследование: Last.fm → MovieLens → отчёт
```

Скрипты сами создают venv, ставят зависимости и скачивают данные и веса с Hugging Face. Нужны bash, curl и Python 3.10–3.13.

В Google Colab: открыть [notebooks/twotower_colab.ipynb](https://colab.research.google.com/github/Sandrolek/rec_sys/blob/main/notebooks/twotower_colab.ipynb), включить T4 GPU и выполнить все ячейки. Ноутбук клонирует репозиторий и запускает те же bash-скрипты.

## Результаты

### MovieLens-100k

Recall@K на тестовом периоде, из выдачи исключены фильмы, которые пользователь уже видел. Прогон на CPU, сид 0; полный отчёт — [results/REPORT.md](results/REPORT.md).

Сплит `user` — по времени внутри истории каждого пользователя, у всех 943 пользователей есть история:

| | Recall@10 | Recall@50 | Recall@100 |
|---|---|---|---|
| Гиперпараметры авторов (3 эпохи, батч 4096) | 0.0116 | 0.0475 | 0.0852 |
| Подбор по val: батч 2048, эпоха 14 | 0.0413 | 0.1659 | 0.2877 |
| То же с поправкой logQ, которой нет у авторов | 0.0885 | 0.3158 | 0.4721 |
| Бейзлайн: популярное | 0.0600 | 0.1835 | 0.2978 |
| Бейзлайн: случайная выдача | 0.0063 | 0.0316 | 0.0633 |

Сплит `global` — общая временная шкала, как у авторов; в тесте 166 пользователей, у 97 из них нет ни одного события в train:

| | Recall@10 | Recall@50 | Recall@100 |
|---|---|---|---|
| Гиперпараметры авторов (3 эпохи, батч 4096) | 0.0144 | 0.0525 | 0.0864 |
| Подбор по val: батч 2048, эпоха 4 | 0.0195 | 0.0821 | 0.1351 |
| То же с поправкой logQ, которой нет у авторов | 0.0833 | 0.2171 | 0.3110 |
| Бейзлайн: популярное | 0.0615 | 0.1992 | 0.3145 |
| Бейзлайн: случайная выдача | 0.0063 | 0.0316 | 0.0633 |

Что из этого следует:

- **Гиперпараметры авторов не переносятся.** 3 эпохи с батчем 4096 на 80 тыс. событий — это 60 шагов градиента. Loss остаётся у ln 4096, модель почти не отличается от случайной выдачи.
- **После подбора батча и числа эпох алгоритм проигрывает топу популярного**: Recall@10 0.041 против 0.060 на сплите `user` и 0.020 против 0.062 на сплите `global`.
- **Причина проигрыша — в функции потерь, а не в архитектуре.** Негативами служат чужие позитивы из батча, популярные фильмы попадают туда чаще и получают заниженные оценки. Та же модель с поправкой logQ обходит популярное: 0.089 против 0.060.
- **Временной сплит авторов упирается в холодный старт.** Башня пользователя — это эмбеддинг по ID, для нового пользователя он не обучен. На MovieLens-100k при общем временном сплите новые 97 из 166 тестовых пользователей. На Last.fm 1K истории многолетние, и таких должно быть мало; точное число покажет запуск в Colab.

### Last.fm 1K

Ещё не посчитано: нужен запуск ноутбука в Colab. После него `results/REPORT.md` дополнится тремя частями: какой протокол оценки воспроизводит числа авторов, метрики их весов и нашего обучения с нуля, сравнение с MovieLens-100k.

Авторы заявляют Recall@10 / 50 / 100 = 0.0708 / 0.2172 / 0.3140 на 847 пользователях и сравнивают только со случайной выдачей.

## Как устроено исследование

**Алгоритм.** Две башни: пользователь (эмбеддинг ID → MLP) и объект (эмбеддинги ID и группы → MLP), выходы нормируются, оценка — скалярное произведение с обучаемой температурой. Обучение — симметричный InfoNCE с негативами из батча, AdamW. Код архитектуры перенесён из HF Space авторов без изменений, поэтому их чекпойнт загружается как есть.

**Воспроизведение на Last.fm 1K** идёт в два шага: оценка опубликованных весов авторов и обучение с нуля с их гиперпараметрами (3 эпохи, батч 4096, lr 1e-3, weight decay 1e-5).

**Протокол оценки.** Репозиторий авторов на GitHub недоступен (404), кода оценки нет, а описание — одна строка: Recall@K на 847 отложенных пользователях с фильтрацией прослушанных треков. Если новых треков у пользователя сотни, обычный recall при K = 100 дать 0.31 не может. Поэтому каждая модель оценивается сразу в нескольких вариантах:

- какой период оценивается (test или val) и что считается уже виденным (train, train + val, ничего);
- пять определений метрики: `recall`, `hit` (хотя бы одно попадание), `recall_capped`, `event` (доля событий) и `first` (следующий новый объект);
- на Last.fm ещё и то, откуда берётся исполнитель трека: из всех данных или только из train, как в демо авторов.

Отчёт находит вариант, ближайший к заявленным числам, и дальше сравнивает всё в нём.

**MovieLens-100k.** Каждая оценка считается взаимодействием «посмотрел фильм». Вместо исполнителя группой объекта служит набор жанров фильма. Архитектура, функция потерь, lr и weight decay не меняются; по val подбираются только размер батча и число эпох.

**Бейзлайны.** Случайная выдача (точные формулы) и топ популярного по числу пользователей в train. Каталоги отличаются на три порядка, поэтому датасеты сравниваются по отношению метрики к бейзлайну, а не по самим значениям.

## Скрипты

| Скрипт | Что делает |
|---|---|
| `scripts/predict.sh [movielens\|lastfm] [N]` | Ставит окружение, скачивает веса и данные, берёт N пользователей из test и печатает вероятности следующего объекта |
| `scripts/reproduce_lastfm.sh [all\|eval\|train]` | Оценивает веса авторов на Last.fm 1K и обучает модель с нуля |
| `scripts/train_movielens.sh` | Обучает модель на MovieLens-100k: оба сплита, гиперпараметры авторов, подбор батча, logQ |
| `scripts/run_all.sh` | Запускает всё подряд и собирает отчёт |
| `scripts/download.sh ЦЕЛЬ...` | Скачивает датасеты и веса через curl |
| `scripts/env.sh` | Создаёт venv и ставит зависимости; подключается из остальных скриптов |

Переменные окружения: `PYTHON=python3.12` — каким интерпретатором создавать venv, `USE_SYSTEM_PYTHON=1` — работать без venv, `WEIGHTS=путь` — свои веса для `predict.sh`.

## Структура

```
twotower/model.py      архитектура авторов, функция потерь, сохранение и загрузка весов
twotower/data.py       Last.fm 1K и MovieLens-100k в общем формате
twotower/train.py      обучение
twotower/evaluate.py   top-K по всему каталогу, варианты протокола, бейзлайны
twotower/predict.py    вероятности следующего объекта
twotower/report.py     сводный отчёт results/REPORT.md
scripts/               bash-скрипты
notebooks/             ноутбук для Google Colab
weights/               веса двух моделей для MovieLens-100k: алгоритм авторов и он же с logQ (по 1.2 МБ)
results/               метрики всех запусков и отчёт
```

## Ресурсы

Бесплатного Colab с T4 хватает. Модель для Last.fm — 107 млн параметров (430 МБ), почти все в эмбеддингах треков; данные — 15.3 млн событий. Оценка времени обучения на T4 — 5–15 минут на 3 эпохи, она не проверена. Проверено на синтетических данных того же размера на CPU: шаг обучения занимает 0.13 с на 18 ядрах, пик памяти 7.4 ГБ. MovieLens-100k целиком считается на тех же 18 ядрах за 9 минут.
