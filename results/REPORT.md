# TwoTower (loopback): Last.fm 1K и MovieLens-100k

Основной протокол: `test/seen=train`, метрика `hit`; в таблицах значения при K = 10 / 50 / 100. На Last.fm 1K вектор пользователя — башня пользователя, исполнитель только у треков из train, пользователи — с историей в train.

## 1. Какой протокол оценки у авторов

Заявлено: Recall@10/50/100 = 0.0708 / 0.2172 / 0.3140 на 847 пользователях. Код оценки недоступен, поэтому веса авторов оценены во всех вариантах протокола; ниже восемь ближайших к заявленным числам (отклонение — худшее из трёх K). Вариантов около двухсот, и близкий может найтись случайно: протокол считаем найденным, только если отклонение — единицы процентов, а пользователей около 847.

## 5. Сравнение

|  | @10 | к случайной выдаче | к популярному |

| Last.fm 1K, веса авторов | 0.0711 | ×20.9 | ×0.3 |

«К случайной выдаче» и «к популярному» — во сколько раз модель лучше бейзлайна при K = 10 (для MovieLens взят запуск с подбором по val). Каталоги отличаются на три порядка: 1.5 млн треков против 1.7 тыс. фильмов, поэтому датасеты сравниваются по этим отношениям, а не по самим значениям метрики.
